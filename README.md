# Петербург в деталях

Пешеходный навигатор для знакомства с Санкт-Петербургом.

**Автор:** Денис Аниськов  
**Слоган:** «Замечай больше. Открывай Петербург»

Публичный исходный код Android-приложения: Flutter-клиент с официальным
Yandex MapKit и внешний FastAPI backend. Репозиторий содержит только
клиентское приложение; серверная часть развёрнута отдельно и в этот
репозиторий не входит.

## Идея

Приложение помогает не просто дойти из точки А в точку Б, а увидеть город по
дороге. Пешеходный маршрут строится по официальному MapKit, а поверх него
приложение показывает то, что обычно остаётся незамеченным: набережные,
пешеходные улицы, площади, необычные места и спокойные тихие участки.
Экологические оценки (тень, влажность поверхности, пыльца, шум) не являются
измерениями — это расчётные оценки по открытым данным, которые помогают
сравнить варианты прогулки, а не заменить здравый смысл.

## Возможности

- **Карта Санкт-Петербурга** — нативный Yandex MapKit Full SDK с метками
  каталога, маркерами старта и геометрией маршрута из ответа SDK.
- **Каталог достопримечательностей** — карточки мест с описаниями, тегами,
  категориями, признаком «необычное место» и проверенными историческими
  справками.
- **Пешеходная маршрутизация** — через `PedestrianRouter` официального MapKit
  для двух точек; расстояние, время и геометрия берутся из ответа SDK.
- **Smart Walk** — редакционный планировщик прогулки по каталогу: типы мест,
  бюджет времени и мягкий приоритет необычных объектов.
- **GPS-навигация** — сопровождение по маршруту с инструкциями манёвров,
  обнаружением отклонения и **ручным** перестроением; подтверждение прибытия
  «Я на месте» также ручное. Разрешение на геолокацию запрашивается при
  запуске навигации независимо от способа выбора точки старта.
- **Scenic** — приоритет scenic-объектов (набережные, пешеходные улицы,
  площади) при планировании прогулки по локальному набору на основе OSM.
- **Shade (тень)** — расчётная оценка затенённости участков маршрута на
  указанное время по модели зданий; это модель, а не измерение.
- **Quiet (тишина)** — относительный прокси шумовой нагрузки по открытому
  снимку дорожной сети; значения не в децибелах.
- **Puddle (влажность поверхности)** — относительная оценка склонности к
  лужам по снимку дорожной сети и модельным осадкам.
- **Pollen (пыльца)** — смоделированные концентрации по видам (CAMS через
  Open-Meteo Air Quality) с указанием вида и покрытия без «уровней
  опасности».
- **Контекстные рекомендации** — предложения по месту, времени суток и
  текущему контексту прогулки.
- **«Открой город»** — редакционная подборка городских впечатлений и мест
  обзора.
- **ИИ-помощник** — встроенный ассистент (бесплатная модель через OpenRouter,
  потоковая выдача по SSE) с отдельным информированным согласием; ответ
  резервной модели помечается предупреждением о возможной неточности.
- **Устойчивость каталога** — ограниченное автоматическое восстановление
  загрузки мест после временных сетевых сбоев (без бесконечных запросов) с
  сохранением последнего успешного списка на карте.
- **Голосовой поиск Android** — системный распознаватель речи и системный
  TTS для озвучивания инструкций.
- **Светлая и тёмная темы**, **избранное** и **работа без регистрации**
  (учётная запись не нужна, все данные остаются на устройстве).
- Раздел «О приложении» — версия, автор и ссылки на официальный сайт и
  публичный репозиторий проекта.

| Слой | Технологии |
| --- | --- |

## Требования

- **Android:** 8.0 (API 26) и выше.
- **Flutter:** 3.47.0 или новее (проверено на 3.47.6 stable), Dart 3.13.0+.
- **JDK:** 21 (сборка Android-части).
- **Android SDK:** platform 36, build-tools из состава AGP 8.13.2.
- **Ключ Yandex MapKit** (мобильный SDK) для запуска приложения.
- **Backend API** — развёрнутый сервер FastAPI или совместимая реализация
  описанных ниже endpoint'ов.

## Конфигурация MapKit

Ключ передаётся как **мобильный клиентский** ключ MapKit и попадает в APK при
сборке: получатель APK может извлечь его независимо от способа передачи.
Ограничивайте ключ на стороне Яндекса (привязка к приложению и подписи) и не
передавайте во Flutter серверные ключи Geocoder/Suggest — они backend'у.

Debug-сборки читают локальный `.env.dev` (файл не коммитится). Release и
profile требуют явных `--dart-define`/`--dart-define-from-file`, иначе сборка
останавливается до компиляции Dart. Порядок приоритета, все переменные и
примеры — в [docs/CONFIGURATION.md](docs/CONFIGURATION.md).

## Конфигурация backend API

Клиент обращается к серверу по `API_BASE_URL` и использует следующие
контракты (префикс `/api/v1`):

| Endpoint | Назначение |
| --- | --- |
| `GET /places`, `GET /places/categories`, `GET /places/{id}` | Каталог, категории, карточка места |
| `GET /places/{id}/history` | Проверенная историческая справка (редакционный набор) |
| `POST /routes/propose-walk` | Предложение прогулки по каталогу (Smart Walk) |
| `POST /routes/evaluate` | Обозначенный контракт будущего этапа: отвечает `not_implemented` |
| `POST /environment/shade/analyze` | Расчётная затенённость участков |
| `POST /environment/quiet/analyze` | Относительный шумовой прокси |
| `POST /environment/puddle/analyze` | Относительная влажность поверхности |
| `POST /environment/pollen/analyze` | Смоделированные концентрации пыльцы |
| `POST /assistant/chat`, `POST /assistant/chat/stream` | ИИ-помощник (JSON и SSE) |
| `GET /search/suggest`, `/search/geocode`, `/search/reverse-geocode` | Внешний поиск и геокодирование |

Расстояние, время и геометрия пешеходного маршрута приходят не из backend, а
из MapKit. Полное описание слоёв и потоков данных —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Debug и release

| | Debug | Release |
| --- | --- | --- |
| Конфигурация | `.env.dev` или `--dart-define` | только `--dart-define`/`--dart-define-from-file` |
| Проверка значений | мягкая | обязательны `MAPKIT_API_KEY`, `API_BASE_URL` (HTTPS), `APP_ENV` = `staging`/`production` |
| HTTP | разрешён (локальный backend) | запрещён (`usesCleartextTraffic="false"`) |
| Подпись | стандартный debug-ключ Android | только постоянный release-keystore из `android/key.properties` |

Без настроенной release-подписи сборка release не выполняется: приложение не
должно выглядеть опубликованным, пока не подписано постоянным ключом. Порядок
хранения ключа и предупреждение о совместимости обновлений —
[docs/BUILDING.md](docs/BUILDING.md).

## Частые вопросы (FAQ)

**Что делать, если GPS-сопровождение сообщает о недоступности геолокации?**

При запуске навигации приложение само запрашивает разрешение на геолокацию
независимо от того, как выбрана точка старта. Сообщение о недоступности
появляется, только если разрешение отклонено или службы геолокации выключены:
разрешите доступ в системном запросе или в настройках приложения и включите
геолокацию устройства — сессия навигации продолжится с тем же маршрутом.
Внутри зданий и при слабом сигнале спутников точность может снижаться — это
ограничение самого GPS, а не приложения.

**Как обновить приложение без потери данных?**

Скачайте новый APK из [GitHub Releases](https://github.com/DenisAniskov/SPb_in_Details_public/releases)
и установите его поверх существующего (Android спросит подтверждение
обновления). Автоматических обновлений нет: приложение распространяется вне
Google Play, и обновления выполняются вручную. Пока подпись совпадает с
исходной, обновление сохраняет избранное, настройки и согласия; удалять
приложение для обновления не нужно.
